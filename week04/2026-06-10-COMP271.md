## Wrapping Up the Dynamic Array

We wrapped up week 4 by completing the `DynamicArray` class we have been building from scratch. The object already supports adding data and searching for it (via `index_of` and `contains`). The missing piece, as Temeeka pointed out early in class, was the ability to remove data.

## Designing the `remove` Method

Before writing any code, we agreed on what removal should look like: when an element is taken out, the remaining elements shift one position to the left so the array stays packed from the front, and the last occupied cell is set to `None`. The removed value is returned to the caller.

We then translated that plan into steps:

1. Validate that the requested index is `>= 0` and `< size` (not capacity).
2. Save a copy of the value at that index (`value_to_return`), initialized to `-1` before the `if` block to avoid a scope error if the index is invalid.
3. Loop `for i in range(index, size)`: set `self.data[i] = self.data[i+1]`, shifting everything left.
4. Set `self.data[size - 1] = None` to clear the last occupied cell.
5. Decrement `size` by one.
6. Return `value_to_return`.

We also discussed the key reason `value_to_return` must be initialized outside the `if` block — otherwise the `return` at the bottom references an undefined variable when the index is invalid.

## Generalizing and Encapsulating

We updated the object to store any data type (not just integers), replacing `-1` sentinel values with `None` where appropriate. We also marked the `__resize` method as private — internal resizing is the object's own business, not something external code should trigger.
