## Type Hints and Python's Flexible Typing

We opened by revisiting the `Node` class and clarifying the role of type annotations. In Python, type hints communicate intent — what type of data a payload is expected to hold — but have no effect on program execution. Python's dynamic typing means we can create two `Node` objects with different payload types without error. By contrast, in Java a type mismatch causes a compile-time error before the program ever runs. As Temeeka observed, Python's flexibility stems from its design as a rapid-prototyping tool; strict typing adds overhead that slows exploratory development. We also touched on why language choice matters little in introductory CS: the core concepts (loops, conditionals, data structures) transfer across languages.

## Building a Doubly Linked List

With the `Node` class established, we began building a `DoubleLinkedList` class. The constructor takes no arguments and initializes three fields: `_head` (None), `_tail` (None), and a node count (0). Each node carries `_payload`, `_previous`, and `_next` — making the list bidirectional, traversable in either direction.

## Finding the Middle Node

We explored finding the middle node of a linked list. The naive approach counts all nodes (one full traversal), divides by $\lfloor n/2 \rfloor$, then traverses again to reach that position — two passes. A more elegant one-pass method uses two cursors: a **slow cursor** moves one node at a time while a **fast cursor** skips every other node. Using a staircase analogy developed with Alexander and Jeleel, we worked out that when the fast cursor reaches the tail, the slow cursor is at the middle. We reinforced why maintaining a node count field is practical: rather than counting on demand, we update by $+1$ on insertion and $-1$ on deletion — so the middle is always reachable in $\lfloor \text{count}/2 \rfloor$ steps from the head without any traversal to count first.
