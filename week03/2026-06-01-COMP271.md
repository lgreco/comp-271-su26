## Topic: Dynamic Arrays - From Fixed Capacity to Automatic Resizing

### Review: where we left off

Last week's program stored zip codes in a fixed-size list pre-filled with `-1` as a sentinel value (meaning "no zip code here yet"). Two variables controlled the structure:

- **`capacity`** - how many slots the list was created with (initially `4`)
- **`size`** - how many real zip codes have been added so far (starts at `0`)

The hotel analogy: a hotel with 100 rooms is not the same as a hotel with 100 guests. `capacity` is the room count; `size` is the occupancy.

The `add()` method used `size` as the index of the next available slot - because slots are filled left-to-right, the count of filled slots is always the index of the first open one. If the array was full, the old version just printed "sorry."

---

### The core question: what happens when the array is full?

Class discussion explored several options:

- **Hardcode a bigger number** - works once, breaks again when you exceed the new limit.
- **Use a variable** - better, but still requires picking a fixed upper bound upfront.
- **Pre-allocate the theoretical maximum** (e.g., one slot per US zip code) - wastes memory for most users; allocating memory you don't intend to use is poor practice even when memory is cheap.

The chosen approach: **double the array size each time it fills up**. This is a policy decision - 50% growth or 3x growth are equally valid choices - but doubling keeps the arithmetic clean and avoids fractional sizes.

---

### The `resize()` method

The resize procedure has three steps:

1. **Create a temporary array** twice the size of the current one, pre-filled with `-1`.
2. **Copy** every element from the current array into the temporary array.
3. **Replace** the current array with the temporary array and update `capacity`.

The `add()` method was updated to call `resize()` automatically before inserting a new value whenever `size >= capacity`, so the caller never has to think about capacity management.

---

### Magic numbers

A **magic number** is any literal integer other than `-1`, `0`, or `+1` appearing directly in code. Those three are exempt because their meaning is nearly universal (empty/sentinel, nothing, one step). Any other literal - like `4` for initial capacity, or `2` for the growth factor - carries a specific meaning that belongs in a named variable.

Using named values instead of magic numbers means:
- The meaning is documented at the point of declaration.
- Every loop, condition, and calculation that references the name stays correct automatically when the value changes.
- There is exactly one place to edit.

Applied to this program:

```python
capacity = 4      # initial size of the array
resize_by = 2     # growth factor each time the array fills up
```

After introducing `resize_by`, the resize logic reads as multiplication of two named values rather than a bare `* 2`, making the policy explicit.

### Transition to the object-oriented version

The procedural version requires `global` declarations inside functions (`global size`, `global zip_codes`, `global capacity`) because Python function scope is isolated - a variable named `size` inside a function is a different variable than one at module level unless `global` is declared. The family analogy: a "John" in one family is not the same "John" in another family.

This limitation disappears with a class. An **object** bundles data and behavior together:

- **Data**: the zip codes list, `capacity`, `size`
- **Behavior**: `add()`, `resize()`, `__str__()`

The class version (`DynamicArray`) uses `self` to access its own data from any method, eliminating the need for `global`. The growth factor becomes a class-level constant `RESIZE_BY = 2`, and the initial capacity is passed as a parameter to `__init__()` so the caller decides the starting size.

```
Object = data + behavior
```

This is the fundamental definition of an object in object-oriented programming.
