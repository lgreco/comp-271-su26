## Reflecting on the File-Based Linked List Assignment

We opened by talking about the linked-list-via-files assignment. With Temeeka's honest account of getting stuck, we discussed why the exercise feels so counterintuitive: it forces us to translate an abstraction we understand intuitively (a chain, like a train line) into the least convenient medium possible — plain files — rather than the easy route of objects with `next` pointers.

## Linked Lists Without Objects

We walked through two pre-object ways to build a linked list. An array can serve as a linked list simply by keeping data sequential (index $i$ points to index $i+1$). If data isn't sequential, we need a second array that stores, for each position, the index of the "next" element — an explicit pointer array standing in for what an object's `next` field would do. Before objects existed, developers used files the same way: each node is a file whose second line names the next file, with `head` and `tail` as fixed anchors.

## Collisions and Namespaces

Since node files get random names, we estimated the odds of two files colliding: with 2 letters + 1 digit ($26^2 \times 10 \times 2 \approx 12{,}000$ names), a list of 10,000 nodes is nearly guaranteed to collide. Longer random names shrink — but never eliminate — that probability, which set up the need for a fast way to check membership.

## Binary Search as a Baseline

Using a hotel-guest-lookup metaphor, we contrasted a linear scan ($\mathcal O(n)$) with binary search on a sorted list: each comparison halves the search space, giving $\mathcal O(\log_2 n)$ lookups — $10$ steps for $1{,}024$ guests, $20$ for a million — at the cost of $\mathcal O(n \log n)$ to sort first.

## Introducing Hashing

We then asked: can we answer "is Garcia here?" in one step? By assigning each guest a room based on the first letter of their last name (a hash function), we get $\mathcal O(1)$ lookup — but at most 26 guests fit, wasting most rooms. Extending the key to two letters raised capacity to about 76% of a 1,000-room hotel while still risking collisions, which we'll resolve tomorrow with linear probing (checking room $+1$ when the expected room is taken). Alexander connected this directly to hash functions in cybersecurity.
