# Linked Lists: Traversal and Adding a Station

We picked up our work on linked lists, building on the station object from last class. Each station object holds two pieces of information: a name and a pointer to the next station — initially `none` until we set it explicitly with the `setNext` method. We demonstrated this interactively in Python with two stations, Howard and Jarvis: calling `setNext` on Howard rewires its next-station pointer from `none` to the Jarvis object, letting us travel from Howard to Jarvis by calling `getNext`.

## Finding the End of the Line

We tackled the day's main question: how do we add a new station to a line when we don't know how many stations already exist? If the line is empty, the new station simply becomes the head. Otherwise, we start a "traveler" at the head and move it forward, one `getNext` call at a time, until it reaches a station with no next station — that's the end of the line. We then call `setNext` on that last station to attach the new one. This traversal costs as many steps as there are existing stations, so adding the nth station takes n steps — a real inefficiency we can later remove by keeping a separate pointer directly to the tail.

## Big O Notation

We introduced Big O as a way to classify how the time to solve a problem grows with its size: constant time (size-independent, like a remembered tail pointer), linear time (proportional to size, like our traversal), quadratic time, and general polynomial time (all practically solvable), versus exponential or factorial time (illustrated with the rice-on-a-chessboard and museum-heist subset-search examples), which become unsolvable even on the fastest computers as the problem grows. We'll formalize these definitions and revisit the train line's tail-tracking design next class.
