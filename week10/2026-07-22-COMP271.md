## Avoiding magic values in the queue's constructor

We continued building our file-backed queue. Our starting point was a constructor with a hard-coded file name and capacity — magic values, or literals with no explanation for where they came from. We replaced them with named constants (`DEFAULT_FILE_NAME`, `DEFAULT_CAPACITY`), letting the constructor accept a user-specified file name and capacity while falling back to defaults when neither is given. We noted that by convention, uppercase names signal "this is a constant," but Python cannot actually stop a program from reassigning one — that enforcement relies on programmer discipline, not the language.

## Constants: convention versus enforcement

To make the point concrete, we used JShell and a compiled Java program to show that Java's `final` modifier truly blocks reassignment — the compiler refuses to even build code that tries to change a final variable. Python has no equivalent; we "rely on the we are all adults here principle."

## Building enqueue and dequeue

With the file created in the constructor, we wrote `isFull()` by comparing size to capacity, then `enqueue()`, which opens the file in append mode and writes the payload followed by a newline, incrementing size on success. We simplified the method so it returns directly based on the fullness check rather than through an intermediate variable.

Dequeue was more involved: we read the first line as the front of the queue, copied all remaining lines into a temporary file, closed both files, and swapped the temporary file in as the new queue file — since a plain text file has no way to remove just its first line directly.

## String literals as magic values

We discussed where to draw the line on magic values: mode strings like `"w"`, `"r"`, and `"a"` are technically string literals, but since they're documented in Python's own reference, treating them as an acceptable exception is a matter of style rather than a hard rule.
