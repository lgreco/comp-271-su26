## From Linear Time to Constant Time

We continued building our linked-list-based train line, now keeping two pointers — one to the head and one to the tail — instead of only a pointer to the head. With only a head pointer, finding the last station meant traversing every station first, a process whose time is proportional to $n$, the number of stations: $O(n)$, linear time. By also tracking the tail directly, we can add a new station in one step: $O(1)$, constant time. We traded a small amount of extra memory (the tail pointer) for a large gain in speed — a classic time–space tradeoff. We also simplified the code by noticing that both branches of an `if`/`else` block assigned the same value to `self.tail`, so that line could be moved outside the conditional.

## Asymptotic Notation: Big O and Theta

Using the analogy of planning for a flight (a "realistic worst-case scenario" versus a "catastrophic" one), we formalized big $O$: $f(n) \in O(g(n))$ when $f(n) \leq c \cdot g(n)$ for some constant $c$. Big $O$ describes a set of functions upper-bounded by $g(n)$ — not a single bound. We then introduced theta ($\Theta$), the *tight* bound: $f(n) \in \Theta(g(n))$ when $c_1 \cdot g(n) \leq f(n) \leq c_2 \cdot g(n)$, squeezing $f(n)$ from above and below. We noted that programmers often say big $O$ when they mean theta.

## Polynomial vs. Exponential Time

We compared a polynomial-time problem ($n^{1000}$) against an exponential one ($2^n$) for small $n$, showing exponential can sometimes be faster in practice, though polynomial always wins as $n \to \infty$.
