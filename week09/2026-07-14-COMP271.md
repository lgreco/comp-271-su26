## Circular Stack Implementation

Picking up from the circular queue we built last time, we worked through the equivalent design for a stack — last in, first out. We tracked two pointers, `front` (the exit) and `back` (the entrance), starting them at the same position on an empty array of capacity 4. Pushing an item moves `back` forward before writing; popping reads from `front` and then advances it. Because subtraction can push `front` below zero, we need a wraparound rule: position $-1$ should map back to the last valid index. We noted that Python already does this for list indexing — `list[-1]` returns the last element, `list[-2]` the second to last, and so on.

## Periodic Boundary Conditions and Modular Arithmetic

We connected this wraparound behavior to *periodic boundary conditions* — a pattern in clocks, military time, and physics simulations of crystal lattices, where reaching the end of a finite structure loops back to the start. For an array of length 4, any index modulo 4 always lands in $\{0, 1, 2, 3\}$, which is exactly how a circular buffer stays valid no matter how far the index climbs. We practiced this with modulo arithmetic examples like $6 \bmod 4 = 2$ and $8 \bmod 4 = 0$, and discussed the discipline of deriving these formulas live — the goal in a technical interview is to demonstrate sound reasoning, not memorized formulas.

## Graphs: Reachability and the Adjacency List

We introduced graphs by asking a plain-English question about a small town map: can you get from town A to town H? Points are *vertices*, connecting roads are *edges*, and asking whether one vertex can reach another is the *reachability problem* — foundational to networking, logistics, and social-network analysis. With Temeeka's help, we described the map's connections aloud and translated them into Python as a list of lists — the *adjacency list* representation, where each town's neighbors are stored as their own list.
