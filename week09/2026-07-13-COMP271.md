## From a student question to array-based stacks and queues

We opened by following up on Temeeka's homework snag: her stack logic kept overwriting itself whenever she adjusted the queue insertion code. That became our launching point for building stacks and queues on top of a plain array, starting from a **bounded collection** superclass that holds the operations common to both — `peek`, `size`, and so on — with `Stack` and `Queue` inheriting from it so we don't duplicate methods.

## Dequeuing: shifting left

Removing from the front of the array always happens at position 0. After removing, we shift the remaining elements — from index 1 through `size` $- 1$ — one position to the left, using a loop that runs from the left end forward.

## The stack insertion pitfall

Inserting at the front of a stack means shifting existing elements to the right first. Here we diagnosed the common bug behind Temeeka's issue: shifting right using a left-to-right loop propagates one value across the whole array instead of moving each value once. The fix is to run the loop **in reverse**, from `size` $- 1$ down to $0$, using `range(size - 1, -1, -1)`.

## Time complexity and why we still use arrays

We compared costs: with arrays, queue insertion is $\mathcal O(1)$ but removal is $\mathcal O(n)$; for a stack, both insertion and removal are $\mathcal O(n)$ since they require shifting. Linked-list versions of these structures achieve $\mathcal O(1)$ for everything, but arrays use far less memory since linked list nodes carry extra overhead.

## Circular arrays: getting to constant time

We reshaped the array conceptually into a circle and introduced two pointers, front and back, that advance using modulo arithmetic ($\text{position} + 1 \mod \text{capacity}$) instead of shifting data. This gets insertion and removal for a queue down to $\mathcal O(1)$ while keeping the memory savings of an array — at the cost of two extra pointer variables. As homework, we're asked to work out the circular stack version on our own.
