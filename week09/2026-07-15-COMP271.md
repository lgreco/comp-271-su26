## From Maps to Adjacency Lists
We continued building our mental model of a graph as a map of towns connected by roads, where some towns can sit on their own island with no connection to the mainland. We reviewed the adjacency list representation: for every vertex, list only its direct neighbors, not the towns it reaches indirectly. Since letters run out quickly once a graph has many vertices, we label vertices with integers starting at 0, the numeric equivalent of the first letter.

## From Adjacency List to Adjacency Matrix
We represented the graph as a list of lists in Python, where the index of each inner list is the label of its vertex. We discussed why a node object with an arbitrary number of pointers to other nodes — a "multi-node" — would work but waste memory, since every added connection means growing that node's list of pointers. We then converted the same graph into an adjacency matrix: an $n \times n$ array where a 1 at row $i$, column $j$ marks an edge between vertices $i$ and $j$, and 0 marks its absence. Because our edges are undirected, the matrix is symmetric, and the main diagonal is always 0 since we do not allow a vertex to connect to itself. We wrote a `produce_adjacency_matrix` method that converts an adjacency list into this matrix and confirmed the printed output matched our hand-drawn matrix row by row.

## Reachability
Using the analogy of always turning the same direction to find your way out of a maze, we wrote a loop with a `visited` list and a `go_next` list to determine whether one vertex is reachable from another. Starting from vertex 0, we traced the algorithm by hand and confirmed vertex 6 is reachable, while Temeeka pointed out that vertices 5 and 7 would never be reached from that starting point. Our assignment for next week is to modify this reachability code so that it stops as soon as the target vertex is found, instead of visiting every reachable vertex first.
