## Reviewing Reversal of a Doubly Linked List

We opened by revisiting the linked list reversal problem, since a few of us had struggled with it. We worked through the idea on a virtual whiteboard: a doubly linked list has nodes connected by "next" and "previous" pointers, plus fixed references to the head (first node) and tail (last node). Simply swapping the head and tail labels isn't enough — the list also has to remain traversable from the new head all the way to the new tail, which means every node's pointers must be flipped.

We traced through the approach with a cursor moving from head to tail, using each node's "next" pointer to find the following node and set that node's "previous" pointer back toward the cursor. Once that forward pass connects all the reversed links, a second pass removes the old "next" pointers, or — more efficiently — we can hold a temporary reference to the previous node and do both steps in a single traversal. We connected the abstract steps to a hands-on demonstration with people pointing their arms to model the pointers.

We also talked about problem-solving process: sketching a solution with pen and paper (or a whiteboard) before writing code, since drawing helps cement understanding, and technical interviews often care more about how we reason through a problem than about polished code.

## Removing the Tail and Head in Constant Time

With Temeeka's help, we worked out how to remove the tail node: capture the node before the tail, set its "next" pointer to none so it becomes the new end of the list, then move the tail reference to that node — three steps, regardless of list size. We then mirrored the process to remove the head: find the node after the head, set its "previous" pointer to none, and move the head reference there. Both operations run in constant time, written $\mathcal O(1)$, since the number of steps doesn't depend on how many nodes are in the list.

We closed by previewing tomorrow's topics: since we can efficiently add and remove nodes from either end of a linked list, this sets up two important abstractions — queues (first in, first out) and stacks (last in, first out).
